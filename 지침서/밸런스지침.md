# 밸런스 지침

작성일: 2026-11-25

## 문서 역할

이 문서는 사용자가 정하는 **밸런스 목표와 검증 기준**을 관리한다.
- `../BALANCE.md`: 현재 구현 수치·공식·설계 의도.
- 이 문서: 달성할 목표, 변경 가능한 범위, 측정 조건, 통과 기준.
- `../PROJECT_STATUS.md`: 실제 작업·검증 결과, 미해결 문제, 다음 행동. 결과는 지침 ID로 연결하고 여기 중복 기록하지 않는다.

2026-11-25 사용자 요청으로 BAL-001~003의 설계 방향을 확정했다. 약 90초 클리어는 BAL-002의 확정 목표이며, 허용 오차·표본·구체적 조작 조건은 아직 미정이다. 지침 확정은 현재 구현의 검증 완료를 뜻하지 않는다. 아래 예시는 작성법 설명용이며 실행 지시가 아니다.

## 작성 및 적용 원칙

1. 지침 하나에 주된 목표 하나를 적고 `BAL-001`부터 고유 ID를 부여한다.
2. 상태는 `초안 / 확정 / 보류 / 폐기`로 구분한다. 사용자가 내린 명시적 지침은 확정으로 기록할 수 있으며 매번 재승인을 요구하지 않는다. 작성 예시나 AI 제안은 자동 확정하지 않는다.
3. 원하는 체감과 수치 기준을 함께 쓴다. 단위, 허용 범위, 대상 플레이어, 스킬 사용 조건, 표본 수를 명시한다. 모르는 값은 `미정`으로 남기고 측정 결과를 꾸며 채우지 않는다.
4. 검증만 요청받으면 수치를 바꾸지 않는다. 조정 요청이 있으면 허용된 변수 안에서 작업한다. 기존 지침을 고칠 때는 개정일·바뀐 기준·대체하는 ID를 적는다. 충돌하는 확정 지침이 있으면 충돌을 설명하고 해당 판단을 유보한다.
5. 필수 기준을 모두 충족하면 `통과`, 하나라도 어기면 `실패`, 필수 기준·측정·표본이 부족하면 `미검증`으로 판정한다. 권장 기준은 별도 의견으로 보고한다.
6. 코드 판독, 자동 로직 검사, 시뮬레이션, 브라우저 실플레이를 구분한다. 자동 검사 통과만으로 체감 난도나 실플레이 목표가 달성됐다고 판단하지 않는다.
7. 변경 전후를 같은 조건으로 비교한다. 버전·커밋과 미커밋 변경 여부, 로컬/배포 주소, 브라우저, 입력 방식, 시도 횟수를 기록한다. 일시정지 시간을 제외한 게임 시간을 사용한다.
8. 실패한 시도도 제외하지 않는다. 클리어 시간·잔여 HP는 성공 시도 기준임을 표시하고, 클리어율은 성공 횟수/전체 시도 횟수로 계산한다. 표본 수·평균/중앙값 등 집계 방식은 검증 전에 정한다.

```markdown

- 작성일 / 개정일: YYYY-MM-DD / 없음

#### 측정 조건과 절차

- 대상 플레이어/숙련도:
- 환경: 버전·커밋·미커밋 변경 여부 / 로컬 또는 배포 주소 / 브라우저 / 입력 방식
```

## 짧게 전달하는 방법

처음부터 모든 칸을 채울 필요는 없다. 아래 네 가지를 전달하면 상세 양식으로 정리할 수 있다. 누락된 필수 검증 조건은 미정으로 표시한다.

```text
대상: 무엇을 조정하거나 검증할지
목표: 어떤 느낌/수치가 되어야 하는지
제약: 바꿔도 되는 것과 유지할 것
통과 기준: 어떤 조건에서 몇 번 측정해 무엇을 만족해야 하는지
```

### EXAMPLE-01 — 일반 웨이브 전투 시간

- 상태: 초안 (양식 설명용, 실제 지침으로 등록하지 않음)
- 목표: 첫 웨이브에서 기본 공격을 익히되 전투가 길어지지 않게 한다.
- 작업 범위: 검증만.
- 조정한다면 허용할 항목: 일반 몬스터 HP만. 용사 능력치·적 수·공격 계수는 유지.
- 조건: 같은 플레이어가 연습 2회 후 10회 측정. 만피·버프 없음으로 시작, 방향키와 Z만 사용, 회피 허용, X/C 금지.

- 통과 기준 예시: 10회 모두 클리어하고 클리어 시간 중앙값 8~12초. 이 범위와 횟수는 설명용 임의 값이며 기존 90초 목표의 확정안이 아님.
- 방식: 브라우저 실플레이. 자동 검사는 피해·웨이브 전환 오류 확인에만 사용.

## 등록된 지침

### 공통 적용 조건

- 작성일: 2026-11-25. 적용: v0.3.2를 기준으로 이후 밸런스 조정·검증에 사용.
- 이번 요청 범위: 지침 등록만. 게임 수치 변경·자동 검증·실플레이는 수행하지 않음.
- 세 지침은 함께 만족시켜야 한다. 정지 공격의 위험을 높이기 위해 정상 플레이의 생존·90초 목표를 훼손하지 않는다.
- 향후 검증 시 정상 플레이 / 공격하지 않고 도망 / 이동 입력 없이 공격의 세 조건을 나누어 비교한다. 동일 버전·시작 상태에서 측정하고 조작·스킬 사용·표본 수를 사전에 기록한다.
- 공통 미정: 일반 유저의 숙련도, 연습·참여자·측정 횟수, Z/X/C 사용 방식, 정상 플레이의 회피 수준. AI가 임의 수치를 확정 기준으로 추가하지 않는다.
- 현재 판정: 모두 미검증. 측정 조건이 부족해도 확인 가능한 결과는 기록하되 전체 통과로 단정하지 않는다.

### BAL-001 — 3분 제한은 정상 플레이에 충분한 여유

- 상태: 확정 (설계 방향). 개정일: 없음.
- 대상: 전체 스테이지의 180초 제한과 시간 압박.
- 목표: 일반적인 플레이에서 3분은 전혀 부족하지 않아야 한다. 타임오버는 의도적으로 도망만 다니고 공격하지 않으며 버티는 경우 정도에 발생하도록 설계한다.
- 유지할 항목: 제한시간 180초. 구체적인 조정 변수는 향후 조정 요청 시 정한다.
- 검증: 정상 플레이의 클리어 시간·남은 시간·타임오버 빈도를 측정하고, 공격 없이 도망치는 조건과 비교한다.
- 필수 방향: 정상 플레이에서 타임오버가 일반적인 실패 원인이 되어서는 안 된다. 공격 없이 생존한 경우 180초에 시간초과로 종료되어야 한다.
- 주의: 도망 플레이에서 반드시 180초 생존하도록 보장하라는 의미는 아니다. 먼저 사망하면 사망으로 기록하고 시간초과 검증과 구분한다.
- 미정: 정상 플레이의 최소 시간 여유와 허용 타임오버율. 단순히 180초 직전에 클리어했다고 충분한 여유로 판정하지 않는다.

### BAL-002 — 일반 유저의 목표 클리어 시간 약 90초

- 상태: 확정 (설계 목표). 개정일: 없음.
- 대상: 일반 3마리 → 엘리트 2마리 → 보스 1마리의 전체 스테이지.
- 목표: 적당히 이동·공격하며 일반적으로 플레이하는 유저가 약 1분 30초에 클리어할 수 있도록 계획한다.
- 측정: 게임 시작부터 최종 보스 처치까지의 게임 내 경과 초. 일시정지 제외. 성공 시도의 개별 시간과 집계값, 전체 시도 대비 클리어율을 함께 보고한다.
- 필수 방향: 정상 플레이의 대표 클리어 시간이 약 90초가 되도록 한다. 모든 시도를 정확히 90초로 강제하는 지침이 아니다.
- 변경 가능한 항목: 향후 조정 요청에서 지정. 이 지침 등록만으로 플레이어·몬스터 수치 변경을 실행하지 않는다.
- 미정: 약 90초의 허용 범위, 평균/중앙값 등 대표값 정의, 요구 클리어율.
- 기존 기록과 관계: 전체 90초 목표는 이번 지침으로 확정. 기존 웨이브별 9/27/54초 및 10/30/60% 배분은 여전히 초기 가정이며 이번 요청으로 확정하지 않는다.

### BAL-003 — 이동 없이 공격만 하면 사망 위험이 존재

- 상태: 확정 (설계 방향). 개정일: 없음.
- 대상: 몬스터 공격력과 회피하지 않는 플레이의 생존성.
- 목표: 이동 없이 무작정 공격만 하면 플레이어 HP가 소모되어 사망하는 경우가 있을 정도로 몬스터 공격력을 밸런싱한다. 이동·회피의 필요성이 느껴져야 한다.
- 향후 조정의 주 대상: 몬스터 공격력. 다른 능력치·패턴까지 변경할지는 별도 조정 범위에서 정한다.
- 측정: 이동 입력 없이 공격하는 조건에서 잔여 HP, 사망 여부·시점·웨이브, 사망 횟수/전체 시도 수를 기록하고 정상 플레이와 비교한다.
- 필수 방향: 정지 공격이 언제나 안전한 공략이 되지 않아야 한다. 모든 정지 공격 시도를 반드시 사망시키거나 정상 플레이까지 필연적으로 사망시키라는 지침은 아니다.
- 조건 구분: 이동 입력 없음과 게임 내 접촉 밀려남은 구분한다. 실제 규칙에 따른 밀려남은 유지하고 기록한다.
- 미정: 공격 방향·시작 위치, Z만 사용하는지 X/C도 사용하는지, 스킬 시점, 목표 사망 빈도·시점. 정지 공격의 위험을 검증할 때는 이 조건을 명시한다.
